# Amergination backend

Подготовка первого размещения и параметры MVP: [deploy/README.md](deploy/README.md).
Для сервера используется отдельный `compose.production.yaml`; `compose.yaml`
остаётся локальной инфраструктурой разработки.

## Локальный запуск

Требуются Python 3.14, PostgreSQL и Redis. Для инфраструктуры можно использовать Docker:

```powershell
docker compose up -d postgres redis
```

Создайте `.env` из `.env.example` и замените `POSTGRES_PASSWORD` и `SECRET_KEY`. Случайный секрет можно получить командой:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Установите зависимости и примените миграцию:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Запустите API:

```powershell
.\.venv\Scripts\python.exe main.py
```

Документация будет доступна по адресу `http://127.0.0.1:8080/docs`.
Страница для проверки просмотра — `http://127.0.0.1:8080/watch`.

## Фронтенд и реальный каталог

Главная: `http://127.0.0.1:8080/`. Пример страницы аниме:
`http://127.0.0.1:8080/anime/shikimori/1735`.
Фронтенд находится в `backend/static`: HTML, CSS и JavaScript, без отдельной сборки.
Главная получает реальные онгоинги и рейтинговую подборку Shikimori.
Новости пока демонстрационные. Вход, регистрация, комментарии, лайки и рецензии
подключены к API. Кнопка добавления в список на странице пока остаётся макетом.
Токен входа хранится в sessionStorage текущей вкладки, выход отзывает его через API.

| GET | Ответ |
| --- | --- |
| `/api/v1/anime/catalog/home?limit=12` | `ongoing`, `popular`, `warnings`; limit от 1 до 30 |
| `/api/v1/anime/catalog/shikimori/{id}` | `details`, `related`, `playback`, `warnings` |
| `/api/v1/anime/catalog/animego/{id}?slug=...` | Карточка AnimeGo с обогащением данными Shikimori при однозначном совпадении |

Описание, жанры и связанные тайтлы берутся из источника. Связанные манга
не попадают в ленту аниме. Описания отображаются как текст, без вставки HTML.
Онгоинги кэшируются на 30 минут, подборка и карточки — до 6 часов.
При сбое одной ленты остальные данные остаются доступны; `warnings` сообщает о сбое.
Демонстрационный каталог не подставляется вместо ошибок источника.

ID Shikimori и AnimeGo независимы. `playback` содержит оба ID и статус
`matched`, `not_found`, `ambiguous` или `unavailable`. Автоматическое сопоставление
требует точного нормализованного русского либо оригинального названия,
совпадения года, типа и единственного кандидата. `method: title_year_kind`
обозначает сопоставление по метаданным, а не подтверждённый источником общий ID.
Неоднозначное совпадение не запускает чужой плеер.
`method: same_source` означает, что пользователь уже выбрал конкретный тайтл AnimeGo.

Ссылки фронтенда имеют вид `/anime/shikimori/{id}` или `/anime/animego/{id}?slug=...`.
Slug AnimeGo не содержит конечный числовой ID. Его нужно передать при первом открытии
карточки, поскольку `/anime/{число}` на самом AnimeGo — страница каталога.
Повторные обращения могут использовать кэш. Старый маршрут фронтенда `/anime/{id}`
сохранён для AnimeGo и требует ранее сохранённую связь либо параметр `slug`.
Постеры и шрифты загружаются из внешних источников.

## Список аниме пользователя

После обновления примените миграции: `python -m alembic upgrade head`.
Все запросы к списку требуют заголовок `Authorization: Bearer <access_token>`.

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/api/v1/users/me/watchlist` | Свой список |
| POST | `/api/v1/users/me/watchlist` | Добавить аниме |
| PATCH | `/api/v1/users/me/watchlist/{entry_id}` | Изменить статус, прогресс или название |
| DELETE | `/api/v1/users/me/watchlist/{entry_id}` | Удалить запись |
| GET | `/api/v1/users/{user_id}/watchlist` | Список другого пользователя |

Пример тела POST:

```json
{
  "anime_source": "shikimori",
  "anime_external_id": "20",
  "anime_title": "Naruto",
  "status": "watching",
  "episodes_watched": 12
}
```

Источники: `shikimori`, `animego`, `kodik`. Статусы:
`planned`, `watching`, `completed`, `on_hold`, `dropped`.
Прогресс — целое неотрицательное число просмотренных серий; он изменяется явно,
без автоматического определения количества серий у внешнего сервиса.
Источник и внешний ID нельзя менять через PATCH.
Повторное добавление того же аниме из того же источника возвращает `409`.

GET поддерживает параметры `status`, `limit` (1–100, по умолчанию 20)
и `offset` (по умолчанию 0) и возвращает массив записей.
Список закрыт по умолчанию. Чтобы открыть его другим авторизованным пользователям,
отправьте `{"show_watchlist": true}` на `PATCH /api/v1/profile/settings`.
Владелец видит свой список независимо от этой настройки.

Тесты списка применяют обе миграции к временной SQLite-базе и проверяют SQL,
HTTP API, права доступа и сценарий регистрации, входа, отзыва и выхода.
Redis в этих тестах заменён тестовым объектом; PostgreSQL и asyncpg
требуют отдельной проверки с работающей инфраструктурой.

## Единые ответы каталога и плеера

Маршруты каталога теперь возвращают собственные модели API. Формат ответов
изменился: клиентам нужно использовать новые имена полей. Схемы доступны
в OpenAPI и на `/docs`.

| Маршруты | Модель и основные поля |
| --- | --- |
| `/api/v1/anime/search`, `/api/v1/anime/animego/search` | Массив карточек: `source`, `external_id`, `title`, `original_title`, `page_url`, `poster_url`, `slug`, `year`, `kind`, `status`, `studio`, `genres`, `score` |
| `/api/v1/anime/details` | Карточка и описание, количество серий, длительность, возрастной рейтинг, даты, темы и лицензии |
| `/api/v1/anime/animego/episodes` | `source`, `external_id`, массив `episodes` с `number`, `title`, `air_date`, `is_released` |
| `/api/v1/anime/animego/voices`, `/api/v1/anime/kodik/info` | `source`, `external_id`, `id_source`, `episodes_total`, массив `translations` с `id`, `name`, `player`, `kind`, `embed_url` и диапазоном серий |
| `/api/v1/anime/animego/stream`, `/api/v1/anime/kodik/stream` | `source`, `external_id`, `id_source`, `episode`, `translation_id`, `translation_name`, `player`, массив `streams` |
| `/api/v1/anime/animego/player` | `source`, `external_id`, `episode`, `translation_id`, `translation_name`, `player`, `embed_url` |

Каждый элемент `streams` содержит `url`, `format` (`hls`, `dash` или `mp4`)
и `quality` (число или `null`, если качество неизвестно). Все доступные форматы
CVH сохраняются. Отсутствие рабочей ссылки или обязательных полей в ответе
парсера возвращает `502`.

Для Kodik параметр `shikimori_id` и поле `external_id` обозначают ID Shikimori,
поэтому `id_source` равен `shikimori`, а `source` — `kodik`.
При добавлении этого аниме в список используйте `anime_source: "shikimori"`.
Для фильма в Kodik передавайте `episode=0`; для сериалов нумерация начинается с 1.
Для прямого потока AnimeGo (`/stream`) параметр `player` принимает `aniboom` или `cvh` и участвует
в выборе озвучки.

Параметр `anime_id` AnimeGo принимает числовой ID (например, `3127`)
или полный slug (например, `naruto-uragannye-khroniki-2-svyazi-3127`).
Перед запросом к парсеру slug преобразуется в числовой ID;
в ответах и ключах кэша используется этот ID. Для расписания, которого нет,
проверяется список серий плеера. Такой же переход выполняется при пустом расписании.
Если оба источника не содержат серий, возвращается `episodes: []`.

Неизвестные значения возвращаются как `null`, списки жанров и тем — как `[]`.
Даты и длительность остаются строками источника. Поле `episodes_text` сохраняет
исходную запись Shikimori (например, `"12 / ?"`), а `episodes_aired`
и `episodes_total` содержат числа, если их удалось определить.

## Просмотр через встроенный плеер

### Устойчивость внешних запросов

По умолчанию общий таймаут одного обращения к внешнему сервису — 20 секунд,
включая повторные попытки. Сетевые запросы AnimeGo и каталога Shikimori имеют
таймаут подключения 3 секунды и ожидания данных 5 секунд.

Временные сетевые ошибки и HTTP 429/500/502/503/504/520 допускают одну повторную
попытку с короткой задержкой. Ошибки 403/404, неверные данные и ошибки разбора
не повторяются. Если источник прислал `Retry-After`, запрос повторяется только
после указанной задержки; при задержке больше 2 секунд повтор пропускается.
Ошибка источника не сохраняется как успешный результат в Redis.

Настройки находятся в `.env.example`: `EXTERNAL_SERVICE_TIMEOUT_SECONDS`,
`EXTERNAL_CONNECT_TIMEOUT_SECONDS`, `EXTERNAL_READ_TIMEOUT_SECONDS`,
`EXTERNAL_SERVICE_ATTEMPTS`, `EXTERNAL_RETRY_MAX_DELAY_SECONDS`.
API возвращает 504 при таймауте и 502 при недоступности источника.
Синхронные вызовы парсера выполняются в отдельном пуле из 8 потоков.
Таймаут API не может принудительно остановить уже запущенный поток;
его сетевые запросы ограничены собственными таймаутами.

На `/watch` доступны поиск AnimeGo, выбор серии и озвучки и встроенный плеер.
Поиск фильтрует выдачу источника по русскому и оригинальному названию и slug.
Все слова запроса должны совпадать с началом слов одного из этих названий;
регистр, пунктуация и различие «е/ё» игнорируются. Точное название показывается
первым, затем названия, начинающиеся с запроса. Исправление опечаток пока не реализовано.
Маршрут `/api/v1/anime/animego/player` принимает `anime_id`, `episode`,
`translation_id` и `player` (`kodik`, `sibnet`, `aniboom`, `cvh`).
Озвучка выбирается по паре `translation_id` + `player`: один ID может повторяться
у разных плееров. Полученный `embed_url` предназначен для iframe.

Встроенный Kodik через AnimeGo работает без `KODIK_TOKEN`.
Отдельные маршруты `/kodik/info` и `/kodik/stream` требуют этот токен.

На страницах Shikimori Kodik также подключается напрямую, без поиска AnimeGo:

- `/api/v1/anime/kodik/catalog?shikimori_id=57779` — озвучки и исходный список серий;
- `/api/v1/anime/kodik/voice-episodes?shikimori_id=57779&translation_id=610` — точные серии выбранной озвучки;
- `/api/v1/anime/kodik/player?shikimori_id=57779&translation_id=610&episode=1` — iframe конкретной серии.

Прямое подключение сериалов использует разрешённую публичную интеграцию Kodik
и настроенный `KODIK_SITE_URL`. Отказ провайдера (`allowed != 1`) соблюдается.
API-ключ не требуется; `/kodik/info` и `/kodik/stream` сохраняют прежний контракт.
Ссылка на сериал разрешается по Shikimori ID, а озвучка и сезон подтверждаются
метаданными самого Kodik. Другие студии и недоступные серии не подставляются.
Каталоги озвучек и ссылки из списка серий кэшируются на 10 минут, отдельно
для адреса сайта, тайтла и озвучки. Одновременные одинаковые запросы объединяются.
Отдельные серии для проверки доступности не запрашиваются.

Интерфейс запрашивает карточку с `defer_playback=true`, после чего Kodik и
остальные плееры через AnimeGo загружаются независимо. Отсутствие тайтла или
ошибка поиска AnimeGo не скрывает прямой Kodik. Поздний ответ другого источника
не сбрасывает выбранную озвучку и серию. При доступном прямом Kodik его студии
не дублируются озвучками того же плеера из AnimeGo.

Миграция `0010_playback_translation_source` добавляет в историю `translation_source`:
`animego` для прежних сохранений и `kodik` для прямой интеграции. Числовые ID
озвучек разных источников не смешиваются; старые записи восстанавливаются через
исходный источник. Перед запуском обновлённого приложения выполните `alembic upgrade head`.

Воспроизведение, реклама и доступность видео зависят от внешнего плеера.
Список серий загружается со всех страниц плеера AnimeGo (по 100 серий на страницу).
Внутренние ID видео сохраняются в Redis вместе со списком на 12 часов: поздние серии
доступны для выбора озвучки и встроенного плеера после перезапуска приложения.
Неполный ответ источника не кэшируется и возвращает 502; таймаут — 504.
Названия и даты из расписания сохраняются при объединении с доступными сериями.
Количество серий в ответе озвучек берётся из полного списка плеера.

Проверить запросы к настоящему источнику можно так:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_viewing --query Naruto --anime-id 103
```

Команда проверяет поиск, наличие серий, озвучки и HTTP-доступность страницы плеера.
Для проверки самого видео откройте `/watch` и запустите воспроизведение.

## Проверка на настоящих PostgreSQL и Redis

После запуска инфраструктуры и заполнения `.env`:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_infrastructure
```

Проверка использует реальные PostgreSQL, asyncpg и Redis. Она применяет миграции
в отдельной временной схеме, проходит регистрацию, вход, изменение профиля,
список аниме, отзыв, выход и проверяет, что отозванный JWT больше не принимается.
Временная схема и созданные проверкой ключи Redis удаляются после запуска.
Пользователю PostgreSQL нужно право создавать схемы. При недоступности сервисов
или неполной конфигурации сценарий не выполняется, команда возвращает ненулевой код.


## Комментарии и рецензии

Читать обсуждение можно без входа. Комментарии и лайки доступны зарегистрированным
активным пользователям. Комментарий содержит от 1 до 250 слов; рецензия — от 250
до 1500 слов и обязательный заголовок. Слова разделяются пробелами и переносами;
пунктуация сама по себе не считается словом, слово с дефисом считается одним.

Право на создание рецензий выдаётся при получении 11 действующих лайков под всеми
комментариями автора, включая разные тайтлы. Один пользователь может поставить
один лайк на комментарий. Лайки себе запрещены. Доступ сохраняется после снятия
лайков или удаления комментариев и хранится в user_profiles.can_write_reviews.
Изменение лайков и выдача доступа используют блокировку строки профиля автора.

На сочетание пользователя, источника и внешнего ID разрешена одна рецензия.
При однозначном обогащении карточки AnimeGo данными Shikimori интерфейс использует
ID Shikimori для общего обсуждения. Редактировать и удалять текст может только автор.
Рецензия обязательно указывает has_spoilers: true/false; у комментария флаг
по умолчанию false. На странице помеченные тексты свёрнуты за предупреждением.
Старые рецензии сохраняются при миграции; новые правила длины проверяются
при создании и изменении текста.

| Маршрут | Действие |
| --- | --- |
| GET /api/v1/comments/ | Лента комментариев: anime_source, anime_external_id, limit (1–50), offset |
| POST /api/v1/comments/ | Создать комментарий: anime_source, anime_external_id, text, has_spoilers |
| PATCH /api/v1/comments/{id} | Изменить свой комментарий: text, has_spoilers |
| DELETE /api/v1/comments/{id} | Удалить свой комментарий и его лайки |
| PUT /api/v1/comments/{id}/like | Поставить лайк; повторный запрос не увеличивает счётчик |
| DELETE /api/v1/comments/{id}/like | Снять свой лайк |
| GET /api/v1/comments/eligibility | Свой доступ к рецензиям, число лайков и порог |
| GET /api/v1/reviews/ | Лента рецензий: anime_source, anime_external_id, limit, offset |
| POST /api/v1/reviews/ | Создать рецензию: источник, ID, anime_title, title, text, has_spoilers, необязательный rating |
| GET/PATCH/DELETE /api/v1/reviews/{id} | Получить, изменить или удалить рецензию |

Ленты возвращают items и total. Комментарии содержат автора, число лайков и
liked_by_me (при переданном токене); рецензии содержат автора, заголовок и флаг
спойлеров. Проверки длины и доступа выполняются на сервере, независимо от интерфейса.


## Ограничение частоты действий

Лимиты хранятся в Redis и общие для всех процессов API. Проверка скользящих
окон и запись разрешённого действия выполняются одним Lua-скриптом с часами
Redis. Одновременные запросы не превышают лимит; отказ из-за паузы между
комментариями не расходует часовой лимит. Смена токена не сбрасывает лимит
пользователя. Ключи содержат HMAC идентификаторов, а не IP и логины в открытом виде.

| Действие | Начальный лимит | По чему считается |
| --- | --- | --- |
| Регистрация | 3 в час | IP |
| Вход | 30 за 5 минут | IP |
| Вход с одним логином | 10 за 5 минут | IP + введённый логин |
| Комментарии | 20 в час и пауза 15 секунд | ID пользователя, все тайтлы |
| Поставить/снять лайк | 30 в минуту суммарно | ID пользователя |
| Создание рецензии | 5 попыток в час | ID пользователя |
| Редактирование/удаление обсуждения | 30 в минуту суммарно | ID пользователя |

При превышении лимита API возвращает 429, заголовок Retry-After (секунды)
и сообщение с временем ожидания. Интерфейс показывает это сообщение в форме
или уведомлении, сохраняя текст черновика. Попытки действий учитываются, даже
если затем проверка пароля, прав или самой публикации завершается ошибкой.

При недоступности Redis защищённые действия возвращают 503 с Retry-After: 5.
Чтение общедоступного обсуждения остаётся доступным. Для IP используется
request.client: модуль лимитов не читает X-Forwarded-For или X-Real-IP.
Если приложение стоит за reverse proxy, доверенные адреса proxy нужно настроить
на уровне сервера; нельзя доверять заголовкам от произвольных клиентов.

Все числа настраиваются переменными из .env.example. Правила 11 лайков,
постоянного доступа к рецензиям и длины публикаций сохранены.

Тесты Lua-скрипта на настоящем Redis запускаются отдельно от обычных тестов:

```powershell
$env:RUN_REDIS_RATE_LIMIT_TESTS = "1"
.\.venv\Scripts\python.exe -m unittest discover -q
```

Они используют отдельные случайные ключи и удаляют их после проверки.


## Подтверждение почты через Gmail

### Повторная регистрация во время разработки

Для удаления конкретного тестового аккаунта из локальной PostgreSQL используйте
команду из корня проекта. Сначала она покажет аккаунт и количество связанных записей:

```powershell
.\.venv\Scripts\python.exe -m scripts.dev_delete_user --email test@example.com
```

Для удаления добавьте явный флаг. При повторной проверке регистрации можно также
сбросить лимиты своего локального IP:

```powershell
.\.venv\Scripts\python.exe -m scripts.dev_delete_user --email test@example.com --confirm --reset-ip 127.0.0.1 --reset-ip ::1
```

Удаляются только найденный аккаунт и связанные с ним профиль, комментарии,
лайки, рецензии, список просмотра, значки пользователя и код подтверждения.
Лимиты ID этого аккаунта сбрасываются; --reset-ip также сбрасывает общие для
указанного IP лимиты регистрации и входа. Остальные аккаунты и Redis-кэш остаются.
Команда разрешена только для POSTGRES_HOST localhost/127.0.0.1/::1.
После удаления выйдите из аккаунта на сайте; старый токен больше не даёт доступ.

SMTP отправитель настраивается в локальном .env:

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USERNAME=your-address@gmail.com
SMTP_FROM_EMAIL=your-address@gmail.com
SMTP_PASSWORD=your-google-app-password
```

Для Gmail нужен пароль приложения Google, основной пароль аккаунта не подходит.
Создать пароль можно на https://myaccount.google.com/apppasswords при включённой
двухэтапной проверке. Вставляйте 16 символов без разделяющих пробелов.
После изменения .env перезапустите приложение. .env исключён из Git;
SMTP_PASSWORD используется как SecretStr и не выводится в диагностику.

Регистрация отправляет письмо с 6 цифрами. Код действителен 120 секунд после
успешной отправки, повторная отправка разрешена после этих же 120 секунд.
Разрешены 5 попыток на код; новый код отменяет предыдущий и сбрасывает попытки.
Подтверждение одноразовое. В базе хранится HMAC кода, не сам код; обновление,
подтверждение и отправка сериализованы блокировкой строки пользователя.

POST /api/v1/auth/email/resend — отправить код текущему пользователю.
POST /api/v1/auth/email/verify — подтвердить код: {"code": "012345"}.
GET /api/v1/auth/email/status — оставшееся время, попытки и статус почты.
Все три маршрута требуют токен входа. Повторные отправки дополнительно ограничены
5 попытками в час на пользователя; EMAIL_SEND_LIMIT_PER_HOUR настраивается в .env.

До подтверждения можно войти и читать сайт, но нельзя публиковать/редактировать/
удалять комментарии и рецензии или ставить/снимать лайки. У старых аккаунтов
почта автоматически не подтверждается: владелец тоже должен получить код.
Поле email_verified в ответах регистрации и /auth/me отражает состояние.
UserProfile.is_verified остаётся отдельным признаком профиля и не даёт обхода.

Если SMTP не настроен или отправка не удалась, API возвращает 503;
регистрация и код откатываются, письмо не объявляется успешно отправленным.
Проверка формата и дубликатов почты выполняется при регистрации, владение
почтовым ящиком подтверждается только введённым кодом.


## Восстановление забытого пароля

В форме входа доступна кнопка «Забыли пароль?». Сценарий: почта аккаунта,
6-значный код, затем новый пароль с повторным вводом. Пароль содержит 8–128 символов.

| POST | Тело запроса |
| --- | --- |
| /api/v1/auth/password/request | {"email": "user@example.com"} |
| /api/v1/auth/password/verify | {"email": "user@example.com", "code": "012345"} |
| /api/v1/auth/password/reset | {"reset_token": "...", "new_password": "..."} |

Маршруты доступны без входа. Письмо отправляется только для активного аккаунта
с подтверждённой почтой. Для неизвестного, заблокированного и неподтверждённого
адреса ответ на запрос кода совпадает с ответом для подходящего аккаунта.
Ошибки проверки кода также не раскрывают существование аккаунта.

Код действует 120 секунд с момента выдачи, допускает 5 попыток и одно успешное
использование. Повторный запрос разрешён после 120 секунд; действующий код
не заменяется раньше. Успешная проверка выдаёт одноразовое разрешение на смену
пароля сроком 5 минут. Это разрешение не является JWT и не даёт доступа к аккаунту.
Новый код отменяет прежнее разрешение. Код и разрешение хранятся только в виде HMAC.

Лимиты Redis: до 10 запросов кода в час с IP, до 5 на почту в час, пауза 120 секунд
для адреса; до 30 запросов проверки/смены за 5 минут с IP. Окна считаются для
неизвестной почты также. Старые JWT аннулируются увеличением users.auth_version
в одной транзакции со сменой пароля: проверка действует и при сбое Redis.
JWT предыдущей версии без поля v остаются действительными до первой смены пароля.
После восстановления нужен новый вход; автоматического входа по разрешению нет.

Очередь писем не нужна: отправка восстановления выполняется BackgroundTasks
после одинакового HTTP-ответа. SMTP-сбой фиксируется без адреса и кода в логе;
пользователь может повторить запрос после паузы. Перезапуск процесса между
ответом и отправкой может прервать письмо — следующий запрос выдаст новый код.

Тесты параллельного использования кода и разрешения на настоящем PostgreSQL:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_password_reset
```

Проверка использует временную схему и удаляет её после завершения.
Письма не отправляются, настоящие аккаунты и пароли не изменяются.
Проверки обработчиков интерфейса:

```powershell
node tests/frontend_auth.cjs
node tests/frontend_password_reset.cjs
```

### Достижения и витрина

Миграция `0007_achievements` добавляет постоянные награды:
подтверждение почты, первое и десятое аниме со статусом «Просмотрено»,

принимает `{"codes": [...]}` — до четырёх разных полученных наград в желаемом
порядке; пустой массив очищает витрину. Неизвестные и неполученные награды
отклоняются. Сохранение ограничено общей квотой редактирования профиля.

числе при скрытом списке аниме; редактор предупреждает об этом до сохранения.
Баллы, магазин и автоматическое публичное размещение наград не добавлены.

наград и смена порядка витрины.

### Редактирование профиля и аватар

На собственной странице профиля кнопка «Редактировать профиль» позволяет

между пересозданиями контейнера. Для локального запуска дополнительная настройка
не требуется. Изображения по этим ссылкам доступны без входа.

Аватар и текст сохраняются отдельными запросами: при частичной ошибке форма
указывает, что уже сохранилось, и сохраняет введённый текст для повторной попытки.

### Адреса страниц аниме

Публичные ссылки имеют вид `/anime/nana-877` или
`/anime/sakamichi-no-apollon-12531`. Имя берётся из оригинального названия,
при его отсутствии — из транслитерации русского. ID определяет тайтл;
изменение текстовой части не переключает страницу на другое аниме.
После загрузки адрес приводится к сохранённому публичному slug, якоря
`#player-section` и `#comments-panel` сохраняются.

При первой регистрации карточек AnimeGo используется точный slug источника и компактный маркер
перед ID: `/anime/nana-a308`. Это отдельное пространство идентификаторов,
поэтому совпадение чисел двух каталогов не смешивает разные произведения.
После подтверждённого сопоставления и обогащения карточки адрес может стать
основным адресом тайтла из Shikimori. Источники и ID внутри API, комментариев,
списков и истории не меняются.

API карточек возвращает вычисляемое поле `public_path`. Frontend использует
одну функцию для ссылок в поиске, лентах, связанных тайтлах, профиле, списках
и истории. Старые `/anime/shikimori/877`, `/anime/animego/308?slug=nana`
и `/anime/308?slug=nana` перенаправляются с HTTP 301. Доступ к плеерам для
построения такого перенаправления не нужен. URL не добавляет HTTPS:
протокол настраивается отдельно при развёртывании.

### Постоянный реестр названий

Миграция `0009_anime_registry` создаёт в PostgreSQL таблицу `anime_registry`.
Составной первичный ключ — `(source, external_id)`; числовые ID двух источников
не смешиваются. Хранятся название, оригинальное название, постоянный
`public_slug`, отдельный `upstream_slug` и даты создания/обновления.
Названия и slug источника обновляются, публичный slug закрепляется первой
успешной записью и автоматически не меняется. Атомарный UPSERT сохраняет его
и при одновременной регистрации одного тайтла несколькими запросами.

Реестр постепенно наполняется проверенными карточками из поиска, подборок,
страниц и связанных тайтлов. Массового обхода внешнего каталога нет. На одну
порцию до 100 уникальных карточек выполняется MGET Redis; отсутствующие или
изменившиеся записи проверяются одним SELECT и при необходимости сохраняются
одним UPSERT. Одинаковые записи не перезаписываются. Повторная выдача карточек
из горячего кэша не обращается к SQL. Обновление Redis выполняется одним
pipeline; ключи `catalog:registry:v1:<source>:<id>` живут 6 часов.

Разрешение известного адреса: Redis → PostgreSQL; внешний источник требуется
только для ещё неизвестного тайтла. После очистки Redis реестр восстанавливает
его записи из PostgreSQL. Для AnimeGo исходный slug можно восстановить даже
без сохранённой в Redis карточки; он не подменяется публичным slug.
Описания, постеры, списки серий и плееры сохраняют прежнюю логику загрузки.

При недоступности БД/Redis просмотр каталога остаётся доступен: есть запасное
формирование ссылки по названию и ID. SQL-операция ограничена двумя секундами;
после ошибки обращения к БД приостанавливаются на 15 секунд. Если оба слоя
недоступны, постоянный slug нельзя подтвердить до их восстановления.

Применение: `python -m alembic upgrade head`. Проверка PostgreSQL отдельно:
`python -m unittest tests.integration_anime_registry -q`. Она пишет только во
временную таблицу внутри откатываемой транзакции и не меняет реальные записи.

### Постеры и недоступные изображения

Каталог получает текущие адреса постеров из Shikimori GraphQL (`poster.mainUrl`)
пакетами до 50 ID. Ответы кэшируются на час, параллельные одинаковые загрузки
объединяются; запросы используют общий лимит Shikimori. Это применяется также
при чтении уже закэшированных страниц, к подборкам, поиску и связанным тайтлам.
Сбой метаданных постеров не скрывает каталог: используются пригодные старые
ссылки. Дополнительная загрузка постеров ограничена пятью секундами.

В старом REST API встречаются `/assets/globals/missing_*.jpg`: это изображения
с надписью «404», которые возвращаются с HTTP 200. Они отбрасываются как
отсутствующие постеры. Относительные и абсолютные адреса нормализуются отдельно.

При отсутствии или ошибке изображения интерфейс показывает локальный
`backend/static/images/poster-unavailable.svg`. Эта защита общая для карточек,
страницы аниме, истории и «Моего списка», включая старые сохранённые ссылки.
Если сама локальная заглушка недоступна, повторная загрузка не зацикливается.
Произвольное содержимое успешно загруженного JPEG не распознаётся: доступность
изображений у внешнего источника гарантировать нельзя.

Прямое подключение Kodik для сериалов уже независимо от AnimeGo. Привязка
Aniboom и CVH пока использует AnimeGo; их прямые источники — следующий этап.
Остальные плееры, включая Sibnet, пока отложены.

### Прогресс просмотра

В блоке просмотра отдельно выбираются плеер, озвучка и серия. После выбора
озвучки загружается полный точный перечень доступных серий с учётом пропусков.
Рядом показано их количество. До выбора озвучки можно выбрать любую серию,
чтобы найти студии, появляющиеся в середине длинного тайтла. При смене
озвучки текущая серия сохраняется, если она доступна; иначе выбирается первая.
Для прямого Kodik список берётся из выбранной озвучки и сезона самого провайдера.
Для плееров через AnimeGo в список попадают только номера, известные и плееру,
и каталогу AnimeGo. Плеер загружается
автоматически; воспроизведение внутри iframe зависит от плеера и браузера.
При ручном выборе озвучки уже подтверждённая текущая серия открывается
параллельно загрузке полного каталога. До его получения переключение серий
заблокировано. Восстановление сохранённого выбора сначала проверяет каталог.

`GET /api/v1/anime/animego/voice-episodes` принимает `anime_id`,
`translation_id`, `player`, `episode` (серия, из которой получена озвучка).
Ответ: `status: ready | unsupported`, `episodes` (точные номера), `message`.
Устаревшее поле `next_offset` всегда `null`, чтобы остановить старые клиенты
с поштучной пагинацией; нового обхода эпизодов нет.

Получение метаданных разделено по плеерам:

- **Aniboom:** свежий embed → каталог episodePicker → пакетные details по 30
  номеров. Каталог общий для переводов, поэтому доступность фильтруется по
  `available` выбранной озвучки. Максимум три одновременных запроса details,
  не более пяти стартов в секунду. Подписанный endpoint не сохраняется;
  успешные полностью проверенные пакеты кэшируются на 10 минут для повтора
  после ошибки одного пакета. Частичный результат не выдаётся за полный.
- **CVH:** один playlist-запрос, фильтрация по сезону из embed, точному
  нормализованному имени студии и типу озвучки. Неоднозначность типа вызывает
  явную ошибку; приблизительное совпадение названий не используется. Записи
  без студии исключаются и не мешают загрузке серий выбранной студии.
- **Kodik:** известный `/serial/...` читается максимум за два HTML-запроса;
  исключаются серии с `data-other-translation=true`. Для обычного `/seria/...`
  сначала используется подтверждённая сервером связь AnimeGo ↔ Shikimori.
  Если настроен собственный `KODIK_TOKEN`, каталог запрашивается одним POST
  `https://kodik-api.com/search` с `with_episodes=true`. Без собственного ключа
  используется публичный механизм вставки самого Kodik: fixed official JS
  `https://kodik-add.com/add-players.min.js?v=2` → POST `get-player` → полный
  serial embed. Публичный клиентский параметр берётся только из официального
  скрипта, кэшируется в памяти на час и не сохраняется в `.env`/Git/браузере.
  Код не использует списки чужих токенов. Ссылка на сериал принимается только
  при `found=true` и `allowed=1`, перенаправления не выполняются. В get-player
  передаётся адрес **нашего** сайта из `KODIK_SITE_URL`, не клиентский Host и
  не адрес стороннего сайта. Серии берутся из точных ключей/option, без вывода
  диапазонов из названий студий. При отсутствии разрешения или подтверждённого
  ID возвращается `unsupported`, без перебора эпизодов.
  Если подпись озвучки AnimeGo отсутствует в serial-каталоге, ID перевода
  берётся из метаданных одной исходной `/seria/` и сопоставляется с `data-id`
  каталога. Это покрывает разные названия студий и общие подписи вроде
  «Профессиональный многоголосый», без нечёткого поиска и обхода серий.
- **Sibnet:** пока `unsupported`; нет подтверждённой привязки полного плейлиста.

Готовые результаты кэшируются в Redis на 30 минут. Ключ включает AnimeGo ID,
плеер, перевод и reference-серию, чтобы не смешивать разные каталоги/сезоны.
Для Kodik ключ кэша дополнительно учитывает подтверждённый Shikimori ID
и хэш настроенного origin сайта.
Одновременные одинаковые запросы разделяют одну загрузку. Вся операция
ограничена `EXTERNAL_SERVICE_TIMEOUT_SECONDS` (по умолчанию 20 секунд).
Ошибка не превращается в пустой список: показывается кнопка повтора.
При `unsupported` остаётся доступна подтверждённая reference-серия, но
полный список не выдумывается. Для поиска другой серии сначала сбросьте
озвучку. Смена озвучки отменяет запрос браузера; устаревший ответ игнорируется.
Очередь задач и миграция не требуются.

Проверки: `node tests/frontend_player.cjs` и
`.\.venv\Scripts\python.exe -m unittest tests.test_voice_episodes tests.test_aniboom_catalog tests.test_cvh_catalog tests.test_kodik_catalog -q`.

Количество просмотренных серий меняется вручную в «Моём списке»
или в окне добавления/изменения тайтла на странице аниме.
Можно исправлять счётчик назад и сбрасывать до нуля. Запуск плеера
и смена серии не увеличивают прогресс, статус просмотра не меняется автоматически.
Статистика профиля учитывает сохранённое количество серий.

API принимает `episodes_watched` как целое число от 0, включая PATCH
существующей записи. Если сервер знает общее количество серий из кэша каталога,
он отклоняет превышение даже при прямом запросе к API. Поле `episodes_total`
в ответе списка показывает эту границу; клиент не может установить её сам.
Данные каталога для границы сохраняются отдельно на 24 часа, если страница
не полностью закэширована из-за недоступности связанных тайтлов или плеера.
При отсутствии метаданных или недоступности Redis общее число неизвестно;
сохранение не вызывает внешних запросов и проверяет только целое неотрицательное
значение в диапазоне PostgreSQL integer. Для обновления метаданных откройте тайтл.
Миграция не требуется.

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_watchlist tests.test_watch_progress -q
node tests/frontend_watchlist.cjs
```

### Kodik: адрес сайта и необязательный собственный API-ключ

Для обычной локальной разработки отдельный ключ не нужен: используется
публичный auto-embed механизм самого провайдера. Связь с Shikimori должна
быть подтверждена сервером при открытии страницы аниме.

По умолчанию адрес нашего сайта — `http://127.0.0.1:8080`. При размещении на
другом домене укажите в `.env` его реальный origin:

```dotenv
KODIK_SITE_URL=https://your-anime-site.example
```

Только схема, домен и при необходимости порт; без пути, пароля и параметров.
Разрешение вставки проверяется для этого сайта: отказ провайдера не обходится.
После изменения настроек перезапустите backend.

При наличии собственного API-доступа можно дополнительно указать:

```dotenv
KODIK_TOKEN=ваш_собственный_ключ
```

Ключ передаётся только в теле запроса на фиксированный API-адрес Kodik и
не отправляется в браузер. В отсутствие собственного ключа не выполняются
попытки взять ключи из сторонних репозиториев или сайтов.

Sibnet пока отложен: нужен доступный пример полного плейлиста с подтверждённой
привязкой к аниме и озвучке либо доступ к официальному API. Одиночный `videoid`
не даёт такого сопоставления. Проверенные публичные страницы метаданных вернули
403; неподтверждённые номера серий и случайные плейлисты не используются.

### История и продолжение просмотра

Примените миграцию `python -m alembic upgrade head` (`0008_playback_history`).
Для авторизованного пользователя после получения корректной ссылки на плеер
сохраняются последняя открытая серия, выбранный плеер, стабильный ID и название
озвучки. Записи хранятся отдельно от списка аниме; просмотренные серии, статусы
и достижения при этом не меняются. Гости историю в аккаунте не сохраняют.

На главной появляется приватная горизонтальная лента «Продолжить просмотр»
с 12 последними тайтлами. Пустая лента скрыта. При возвращении на страницу
аниме последний выбор восстанавливается после проверки доступности серии,
плеера и озвучки. Если выбор устарел, пользователь получает сообщение и выбирает
доступный вариант. Ручные действия отменяют ещё выполняющееся восстановление.
Таймкод и окончание просмотра через чужой iframe пока не определяются.

Кнопки «Предыдущая серия» и «Следующая серия» используют точный список выбранной
озвучки, пропускают отсутствующие номера и отключаются на границах или пока
полный каталог недоступен. Ошибки загрузки истории и сохранения показаны явно;
сохранение можно повторить, не перезагружая плеер.

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/api/v1/users/me/playback-history?limit=12&offset=0` | Последние открытые тайтлы |
| GET | `/api/v1/users/me/playback-history/{source}/{id}` | Сохранённый выбор одного тайтла |
| PUT | `/api/v1/users/me/playback-history/{source}/{id}` | Сохранить или обновить выбор |

Поддерживаются источники `shikimori` и `animego`. Доступ требует авторизации;
чужую историю нельзя прочитать даже при открытом списке аниме. Ответы имеют
`Cache-Control: private, no-store`. Сохранение не обращается к внешним провайдерам.
Повторное сохранение обновляет одну запись пользователя и тайтла, без дубликатов.

Проверки:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_playback_history -q
node tests/frontend_playback_history.cjs
node tests/frontend_player.cjs
node tests/frontend_auth.cjs
```
