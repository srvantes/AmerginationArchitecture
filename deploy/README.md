# Первый запуск Amergination

## Решения для MVP

- Домен: **amergination.com** (оформление и оплата ещё не выполнены).
- Бюджет VPS: **1 500–3 000 ₽ в месяц**, домен оплачивается отдельно.
- Один Linux VPS: FastAPI, PostgreSQL 17, Redis 7, Caddy с HTTPS.
- Сначала небольшая группа тестирующих, затем открытый запуск после проверки на сервере.
- Точная локация сервера ещё не выбрана: она зависит от основной аудитории.

Каталог, поиск, аккаунты с подтверждением почты, профили, список аниме,
комментарии/рецензии, выбор серий и история уже входят в первую версию.
Магазин, платные фоны, Sibnet и сохранение таймкода можно добавлять после запуска.

Видеофайлы не хранятся и не транскодируются на нашем VPS: браузер открывает
iframe провайдера. Требования к VPS здесь относятся к сайту, базе, кэшу и парсерам.
Стартовая оценка — 2 vCPU / 4 ГБ RAM / 40–60 ГБ SSD; дополнительный запас
4 vCPU / 6–8 ГБ RAM / 80 ГБ SSD также помещается в выбранный бюджет у ряда хостеров.
Фактическую нагрузку нужно измерять после запуска.

Для нашего стека подходит **Medium: 3 vCPU / 4 ГБ RAM / 40 ГБ NVMe**.
Есть KVM, root-доступ и Docker Compose; платная панель не нужна.
[Страница тарифов](https://ishosting.io/ru/vps),
[Docker VPS](https://ishosting.com/en/vps/apps/docker).

В [официальном сравнении тарифов](https://blog.ishosting.com/ru/vultr-alternative)
указаны **$24.99 за месяц при помесячной оплате** и $21.24 в пересчёте на месяц
при годовой. Итог в рублях зависит от способа оплаты и конвертации. Условия IPv4
на страницах расходятся: карточка тарифа помечает его как дополнительный,
статья — как включённый. Перед оплатой проверить итог заказа с одним публичным IPv4.

До покупки получить подтверждение поддержки по нашему сценарию:

> Можно ли разместить каталог аниме с внешними iframe-плеерами? Видеофайлы
> не храним, не транскодируем и не проксируем через VPS. На сервере только
> сайт, API, PostgreSQL и Redis. Доступен ли исходящий smtp.gmail.com:465
> на Medium в выбранной локации для писем подтверждения и восстановления пароля?

Это существенное условие: [правила VPS](https://help.ishosting.com/ru/dedicated-servers-and-vps-terms-and-conditions)
ограничивают высоконагруженные и стриминговые сервисы. Отсутствие нашего
видеотрафика само по себе не подтверждает разрешение провайдера.
Те же правила запрещают SWAP на SSD/NVMe, поэтому рассчитывать на него нельзя.

В [официальной инструкции SMTP](https://blog.ishosting.com/en/chatto-on-vps)
Medium и выше указаны как не затронутые блокировкой SMTP, в отличие от Lite/Start.
На реальном VPS всё равно проверить подключение и доставку письма.
[Еженедельные копии](https://help.ishosting.com/ru/vps-backup) для дисков до 100 ГБ
включены, хранятся 4–5 снимков; они дополняют наши копии PostgreSQL и аватаров.
Оплата картой российского банка не подтверждена
[перечнем способов оплаты](https://help.ishosting.com/ru/payment-methods-and-period-balance-replenishment-terms-of-crediting-payments).

Если поддержка подтвердит размещение и подойдёт оплата, начать с одного месяца,
Ubuntu 24.04 LTS и Medium. Локацию выбрать после уточнения аудитории и проверки
сетевой доступности источников. Заказ и оплата ещё не выполнены.

## Что подготовлено в репозитории

- `compose.production.yaml`: приложение, миграция, БД, Redis и HTTPS-прокси.
- `Dockerfile`: Python 3.14, приложение работает от UID/GID 10001.
- `deploy/Caddyfile`: HTTPS, обратный прокси и сжатие.
- `.env.production.example`: только шаблон, без рабочих секретов.
- `deploy/backup.sh`, `deploy/restore.sh`: резервная копия PostgreSQL и аватаров;
  порядок и ограничения описаны в `deploy/README-backups.md`.

Проверено локально 22.10.2026: 244 backend-теста с настоящим Redis, сборка
Linux-образа, запуск полного Compose на пустой PostgreSQL 17, HTTPS и восстановление
копии БД вместе с аватаром. Восстановление проверено также при наличии таблицы,
добавленной после снимка; старый JWT перестал работать после смены `SECRET_KEY`.
Для этого использовалось отдельное временное окружение; проверка реального VPS,
домена, доставки почты и внешних источников ещё предстоит.

PostgreSQL/Redis и порт приложения не публикуются на хосте. Наружу у Compose
выходят только TCP 80 и 443 прокси. SSH на VPS настраивается отдельно.
Приложение доверяет forwarded headers только Caddy по адресу `172.30.80.2`.
Если эта подсеть уже занята, необходимо согласованно изменить subnet, два
статических адреса и `--forwarded-allow-ips` в Compose.

Сохраняются volumes БД, Redis AOF, аватаров и сертификатов. У Redis установлен
лимит 256 МБ с `noeviction`: данные отзыва токенов не вытесняются кэшем.
Логи контейнеров ограничены 3 файлами по 10 МБ.

## Порядок первого размещения

### 1. Выбрать и оформить инфраструктуру

Оформить домен на свой аккаунт, арендовать VPS помесячно, выбрать Ubuntu 24.04 LTS.
Платная панель управления сайтом для этого Compose не требуется.
Установить Docker Engine и Compose plugin по
[официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
Для доступа настроить SSH-ключ; приватный ключ и пароли остаются у владельца.

### 2. Загрузить проверенную версию

Зафиксировать текущие изменения в Git, загрузить нужный коммит на VPS,
например в `/opt/amergination`. Использовать отдельную серверную БД,
без автоматического переноса локальных аккаунтов и тестовых записей.
Если локальные данные понадобятся, это отдельный контролируемый перенос.

Все команды ниже выполняются из корня проекта на VPS.

```bash
cp .env.production.example .env.production
chmod 600 .env.production
```

В `.env.production` заполнить:

- `POSTGRES_PASSWORD`: новый случайный пароль серверной БД.
- `SECRET_KEY`: новый случайный ключ, минимум 32 символа.
- `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`: данные отправителя.
  Для Gmail нужен уже знакомый пароль приложения Google.
- `SITE_DOMAIN=amergination.com`.

Секреты генерируются и вставляются только локально. Пример генерации одного значения:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

`.env.production` исключён из Git и Docker build context. Не копировать рабочую
`.env` с компьютера целиком: адреса БД/Redis, ключ сайта и пароль БД для сервера другие.
Не публиковать вывод `docker compose config`: обычный вывод раскрывает подставленные секреты.
Для проверки использовать `config --quiet`.

### 3. Привязать домен и запустить

Создать DNS A-запись корня `amergination.com` на публичный IPv4 VPS.
Если у сервера нет настроенного IPv6, не добавлять AAAA-запись.
Разрешить входящие 80/443 и SSH; БД и Redis оставить внутри Docker-сети.

```bash
docker compose --env-file .env.production -f compose.production.yaml config --quiet
docker compose --env-file .env.production -f compose.production.yaml up -d --build --wait
docker compose --env-file .env.production -f compose.production.yaml ps
```

Compose сначала ждёт PostgreSQL, запускает `alembic upgrade head`, затем приложение
и после его готовности Caddy. [Caddy получает и обновляет сертификат автоматически](https://caddyserver.com/docs/automatic-https)
при правильном DNS и доступных портах 80/443.

### 4. Проверить с настоящего VPS и домена

1. Открывается HTTPS без предупреждений; HTTP переводит на HTTPS.
2. Регистрация: письмо приходит, код обязателен; работает восстановление пароля.
3. Поиск, карточка аниме, Aniboom/CVH/Kodik работают с внешнего IP VPS.
4. История сохраняет серию/озвучку и восстанавливается после повторного входа.
5. Комментарии, рецензии, приватность профиля и списка проверены двумя аккаунтами.
6. Аватар сохраняется после пересоздания контейнера приложения.
7. Ограничения запросов видят разных посетителей по их реальным IP.
8. Создана резервная копия и проверено восстановление в отдельном окружении.

Для Kodik production Compose задаёт `KODIK_SITE_URL=https://amergination.com`.
Разрешение провайдера для реального домена нужно проверить заново: успешная
локальная проверка не подтверждает доступ для любого домена/IP.

Перед приглашением широкой аудитории убрать демонстрационные новости,
опубликовать контакты проекта и подготовить способ обработки жалоб/модерации.

## Состояние и эксплуатация

```bash
curl --fail https://amergination.com/health/live
curl --fail https://amergination.com/health/ready
docker compose --env-file .env.production -f compose.production.yaml logs --tail=100 app proxy
```

`live` проверяет процесс. `ready` возвращает 200 только при доступных PostgreSQL
и Redis, иначе 503; общий срок проверки 3 секунды. Отправка почты и сторонние
каталоги в readiness не входят.

В серверном Compose включён лимит публичных запросов каталога: 120 в минуту
с одного IP (`CATALOG_LIMIT_PER_MINUTE`). Redis необходим для этой защиты;
при его недоступности такие API возвращают 503. Локально флаг по умолчанию выключен.

Резервные копии должны регулярно уходить на другой носитель/сервер: один volume
или архив на том же VPS не защищает от потери VPS. Скрипты создают локальный
согласованный комплект, но подключение внешнего хранилища и расписания выполняется
после выбора инфраструктуры. Ограничения и команды — в `README-backups.md`.

Для обновления: сначала backup, затем новый проверенный коммит/образ и миграции.
Не выполнять `docker compose down -v` на рабочем сервере: это удалит volumes.
Восстановление базы и возврат версии приложения проверять на отдельном окружении.
